## C++ 知识点

### `std::vector<std::string>`

动态数组，用来保存多条待办事项：

```cpp
std::vector<std::string> todos;
```

### `push_back`

向列表末尾添加元素：

```cpp
todos.push_back(todo);
```

### `getline`

读取包含空格的一整行文本：

```cpp
std::getline(std::cin, todo);
```

使用 `std::cin >> todo` 会在空格处停止，因此菜单选项读取后需要先执行：

```cpp
std::cin.ignore();
```

清理输入缓冲区中的回车符。

### `do...while`

让菜单至少显示一次，并在用户没有选择退出时继续循环：

```cpp
do {
    // 菜单逻辑
} while (choice != 0);
```

### 遍历列表

```cpp
for (std::size_t i = 0; i < todos.size(); ++i) {
    std::cout << i + 1 << ". " << todos[i] << "\n";
}
```

## 主要命令

创建功能分支：

```powershell
git switch main
git pull
git switch -c feature/cli-todo-v01
```

编译：

```powershell
g++ .\src\cli_todo.cpp -o .\build\cli_todo.exe
```

运行：

```powershell
.\build\cli_todo.exe
```

提交：

```powershell
git add .\src\cli_todo.cpp
git commit -m "feat: add initial CLI todo program"
```

推送功能分支：

```powershell
git push -u origin feature/cli-todo-v01
```

合并后同步：

```powershell
git switch main
git pull --prune
git branch -d feature/cli-todo-v01
```

## 遇到的问题

推送 GitHub 时曾超时。原因是本机 `hosts` 将 GitHub 域名解析到 `127.0.0.1`，同时 Steam++ 加速器在本地 443 端口运行，但其转发或证书状态异常。

处理方法：

- 刷新 DNS 缓存：`ipconfig /flushdns`
- 重新开启或修复 Steam++ 的网络加速
- 使用 `git ls-remote origin` 验证连接

网络恢复后，`git add`、`git commit` 和 `git push` 均成功。

## 复习：Git 与 cli-todo 整体流程

### 工具分工

```text
VS Code          写代码、查看文件和 Git 修改
PowerShell       执行 Git、编译和运行程序
g++              把 C++ 源文件编译成 exe
Git              在本地记录代码历史
GitHub           保存远程仓库并进行 PR 协作
```

### 完整开发流程

```text
更新 main
-> 创建功能分支
-> 在 VS Code 修改代码
-> 使用 g++ 编译
-> 运行和测试
-> git status 查看变化
-> git add 放入暂存区
-> git commit 保存本地历史
-> git push 上传功能分支
-> 在 GitHub 创建 PR
-> 检查并合并
-> git pull 同步本地 main
-> 删除功能分支
```

### Git 核心词

| 名称 | 简单含义 |
|---|---|
| Repository | 被 Git 管理的项目 |
| Working tree | 当前正在编辑的文件 |
| Staging area | 下一次提交的待提交清单 |
| Commit | 本地的一次代码存档 |
| Branch | 指向提交的命名时间线 |
| Remote | GitHub 等服务器上的仓库 |
| origin | 远程仓库的默认简称 |
| main | 主要开发分支 |
| Pull Request | 请求把一个分支合并到另一个分支 |
| Merge | 真正执行合并 |

### 命令快速回顾

| 命令 | 含义 |
|---|---|
| `git status` | 查看当前文件和分支状态 |
| `git pull` | 从远程下载并更新当前分支 |
| `git switch main` | 切换到 main 分支 |
| `git switch -c feature/name` | 创建并切换到新分支 |
| `git add file` | 把修改放入暂存区 |
| `git commit -m "..."` | 创建本地提交 |
| `git push` | 上传已经提交的内容 |
| `git push -u origin branch` | 上传功能分支并建立跟踪关系 |
| `git branch -a` | 查看本地和远程分支 |
| `git branch -d branch` | 安全删除已经合并的本地分支 |
| `git log --oneline --decorate` | 查看提交历史和分支位置 |
| `git ls-remote origin` | 测试远程连接并查看远程分支 |

### 最容易混淆的四个动作

```text
git add      = 选择这次要提交的修改
git commit   = 保存到本地历史
git push     = 上传到 GitHub
git pull     = 从 GitHub 下载更新
```

```text
Branch       = 一个工作分支
PR           = 请求合并分支
Merge        = 真正完成合并
```

### git status 常见状态

| 输出 | 含义 |
|---|---|
| `?? file` | 新文件，Git 还没跟踪 |
| `modified` | 文件已修改但未暂存 |
| `Changes to be committed` | 修改已经暂存，准备提交 |
| `working tree clean` | 没有未提交修改 |
| `ahead by 1 commit` | 本地比远程多一个提交 |
| `up to date with origin/main` | 本地和远程已经同步 |

### cli-todo 程序流程

```text
创建空的 todos 列表
-> 显示菜单
-> 读取 choice
-> choice 为 1：读取一行文本并 push_back
-> choice 为 2：遍历并显示 todos
-> choice 为 0：退出循环
```

### C++ 关键点

- `std::vector<std::string>`：保存多条文本待办
- `push_back`：向容器末尾添加元素
- `std::cin >> choice`：读取菜单编号
- `std::cin.ignore()`：清理读取编号后留下的回车符
- `std::getline`：读取包含空格的一整行文本
- `do...while`：让菜单反复出现
- `todos.empty()`：判断待办列表是否为空
- `todos.size()`：获取待办数量
- `todos[i]`：访问第 i 条待办，展示时使用 `i + 1`

### 网络问题回顾

GitHub 推送超时的原因是本机 hosts 将 GitHub 域名指向 `127.0.0.1`，而 Steam++ 加速器的本地转发状态异常。刷新 DNS 并修复或重新开启加速器后，`git ls-remote origin`、`git push` 均恢复正常。
