# 2026-10-12：提示词与上下文（阶段 2 第 1 课）

## 今日目标

- 理解同一条需求，信息完整度不同，结果差异会很大
- 掌握提示词三要素：目标、上下文、约束
- 分析自己真实的一条提示词并改进

## 三要素

| 要素 | 回答的问题 | AI 能知道吗 |
| --- | --- | --- |
| 目标 | 我到底要什么 | 猜不到 |
| 上下文 | 我的环境、代码、已尝试过什么 | 看不到 |
| 约束 | 格式、不许改的地方、性能要求 | 不知道 |

关键：AI 一个都猜不到，它只能拿着你给的信息去预测“最像的答案”。

## 我的真实提示词

原始写法：

```text
写一个判断质数的函数
```

后续动作：

```text
自己再结合整体代码修改一下
```

## 分析

缺失的信息：

- 目标不清：什么语言、函数签名、返回值
- 上下文缺失：项目风格、已有代码、自己学过哪些语法
- 约束缺失：`n` 为 0、1、负数时怎么办，是否追求性能，是否只要函数

隐藏成本：

- “自己再改一下”等于把“补全信息”的工作从 AI 转嫁给自己
- 每改一次就是一轮往返，改 3 次等于问了 3 次

需要澄清的一点：

- 短提示词不是永远错。简单、无歧义的任务（写个质数判断函数）一句话就够
- 真正的技能是判断：这个任务属于“一句话就够”，还是“必须补上下文”

## 改进后的提示词

```text
用 C++ 写一个函数 bool isPrime(int n)，判断 n 是否为质数。

要求：
- 0、1 和负数都返回 false
- 不追求最优性能，写法简单清晰即可
- 只写函数本身，不要 main，不要改动其他代码
- 4 空格缩进，风格和我的 cli-todo 保持一致
```

三要素对照：

| 要素 | 在改进版里的体现 |
| --- | --- |
| 目标 | C++、`bool isPrime(int n)`、判断质数 |
| 上下文 | 自己的 `cli-todo` 风格、4 空格缩进 |
| 约束 | 边界处理、性能要求、只输出函数 |
